# v0.1 — Events P1: Afisha into review, Desk's Events page on dev

*Last updated: 2026-11-10*

**Status:** 🔄 In progress · **Type:** Feature · **Started:** 2026-11-10 · **Completed:** —

The P1 slice of the Events integration (wow-two-ws `system/sessions/events-integration/events-integration.md` #13,
#35): the whole contract in every form, the SCFD pull consumer, review, tracking, imports and the console, deployed
to dev by Wheelhouse. Picks: `../../backlog.md` § Integration picks.

### Iteration 1 — Contract and schema

- [x] Ability to name every Events capability in one contract: catalogs, events, review and observations, tracking,
  workflows, imports, calendar export and intake status (`packages/Abstractions`).
- [x] Ability to store them: migration `002-catalog` (catalogs, events with their date spans and deadlines, sources,
  observations, source posts, intake cursors, workflows, tracking and its history, the import id map).
- [x] Ability to share one rule set across the module: the caller from `ICurrentPrincipal`, honest date spans, facts
  validation, catalog record rules, paging cursors (`packages/Module/Shared`).
- [x] The template's Greetings sample removed from the backend.

### Iteration 2 — Catalogs, events, review and intake

- [x] Ability to create a catalog owned by the caller's organization and read only what the caller may see; a catalog
  holding sourced records stays private (events-integration #50).
- [x] Ability to list, filter, read and curate a catalog's events, honest about date precision; members propose
  candidates (`ProposeAsync`).
- [x] Ability to pull SCFD subscriptions (`AddEventsIntake`): observations and cursor in one transaction behind a
  locked cursor row, dedup by delivery id, the highest revision per post of an SCFD instance across subscriptions,
  malformed records and non-private catalogs quarantined, lifecycle records and purges kept as evidence, sourced
  images never copied into facts.
- [x] Ability to review: accept, reject, merge candidates; apply or dismiss a source's change to a published event.

### Iteration 3 — Tracking, workflows, imports and calendar

- [x] Ability to track a catalog's events per organization with a workflow, history and summary; the owner organization
  tracks its candidates too.
- [x] Ability to import a `wow2.events-import.v1` bundle with a dry run and a stable id map, keeping each producer row
  (`legacy`) as evidence.
- [x] Ability to export published events and exact deadlines as iCalendar (no `VTIMEZONE` block yet).
- [x] Tests: 66 integration (Catalogs, CatalogEvents, Review, Intake, Tracking, Workflows, Imports, Calendar), 26 unit
  (SCFD mapper, calendar writer), 4 migrations.

### Iteration 4 — Client, service and conformance

- [x] Ability to call every broker over HTTP (`AddEventsClient()`, person or service tokens), errors mapped by status.
- [x] Ability to serve the contract with Identity's tokens: a policy per scope plus the person's `events:*`
  permission, trusted issuers with per-issuer audiences, revocation signals at `/signals/identity`.
- [x] Ability for a reviewer to sign in to the console through Identity's BFF (`/api/identity`), the session kept in
  the service's database (`distributed_cache`) and its cookie under a key ring on the keys volume.
- [x] Ability to check SCFD from the image: `intake check` prints each source's pull, tenants and foreign statuses,
  never a token or host.
- [x] One conformance suite per broker passing against the module and the client: 108 cases.
- [x] Tests: E2E 38 (auth 401/403, other audience, service read, signals, console, intake check, migrate verbs), unit
  45, integration 66, conformance 108, migrations 4.

### Iteration 5 — fe package and review console

- [x] Ability to show a catalog's feed, deadlines, detail, proposal and tracking forms from `@wow-two-beta/fe-events`
  (`./kit`), and the review queue, observations with their evidence and intake status (`./admin`).
- [x] Ability for a reviewer to sign in through the catalog owner's Identity and review in the console (`/`,
  `/observations`, `/events`, `/intake`).
- [x] fe tests: fe-events 42, web 15; `check:package` verifies 3 exports and 46 names.

### Iteration 6 — Verification on dev

- [x] Release image `v0.1.1` (`8e0234f`, asset `events-release.tar.gz`): CI's backend and frontend tiers, the bundle and
  the released-image check (boot, migrate, status, pages, 401 without a token) pass; fixed on the way: timestamps at
  PostgreSQL's microsecond precision (Linux runners), the delivery pin v0.13.0 → v0.16.0 for linked keys.
- [x] `v0.1.2`: intake tokens name SCFD's resource (Identity refused them with `invalid_target`); `intake check`'s
  last line carries every status; the worker logs each poll.
- [x] Ability to provision as the deploy's operator: `catalog ensure` and `workflow put` (no person token, Desk's
  exchange grant unchanged), and to import a bundle from the console's `/imports` page with a dry run first.
- [ ] Deploy through Wheelhouse (`deploy.yml`), PostgreSQL, typed issuer and SCFD settings.
- [ ] A live Afisha record becomes a review candidate; nothing publishes unreviewed.
- [x] Tests named for replay, out-of-order revisions, a crash around the cursor commit, a malformed record and a
  cross-organization read pass (locally and in CI on `8e0234f`).
