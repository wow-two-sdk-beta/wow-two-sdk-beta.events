# v0.1 — Events P1: Afisha into review, Desk's Events page on dev

*Last updated: 2026-11-10*

**Status:** 🔄 In progress · **Type:** Feature · **Started:** 2026-11-10 · **Completed:** —

The P1 slice of the Events integration (wow-two-ws `system/sessions/events-integration/events-integration.md` #13,
#35): the whole contract in every form, the SCFD pull consumer, review, tracking, imports and the console, deployed
to dev by Wheelhouse. Picks: `../../backlog.md` § Integration picks.

### Iteration 1 — Contract and schema

- [x] Ability to name every Events capability in one contract: catalogs, events, review and observations, tracking,
  workflows, imports, calendar export and intake status (`packages/Abstractions`).
- [x] Ability to store them: migration `002-catalog` (catalogs, events with their date spans and deadlines, sources,
  observations, source posts, intake cursors, workflows, tracking and its history, the import id map).
- [x] Ability to share one rule set across the module: the caller from `ICurrentPrincipal`, honest date spans, facts
  validation, catalog record rules, paging cursors (`packages/Module/Shared`).
- [x] The template's Greetings sample removed from the backend.

### Iteration 2 — Catalogs, events, review and intake

- [ ] Ability to create a catalog owned by the caller's organization and read only what the caller may see.
- [ ] Ability to list, filter, read and curate a catalog's events, honest about date precision.
- [ ] Ability to pull an SCFD subscription: observations and cursor in one transaction, dedup by delivery id, the
  highest revision per post, malformed records quarantined, lifecycle records kept as evidence.
- [ ] Ability to review: accept, reject, merge candidates; apply or dismiss a source's change to a published event.

### Iteration 3 — Tracking, workflows, imports and calendar

- [ ] Ability to track a catalog's events per organization with a workflow, history and summary.
- [ ] Ability to import a `wow2.events-import.v1` bundle with a dry run and a stable id map.
- [ ] Ability to export published events and exact deadlines as iCalendar.

### Iteration 4 — Client, service and conformance

- [ ] Ability to call every broker over HTTP (`AddEventsClient()`, person or service tokens).
- [ ] Ability to serve the contract with Identity's tokens: scope plus organization permission, revocation signals.
- [ ] One conformance suite passing against the module, the client and the fakes.

### Iteration 5 — fe package and review console

- [ ] Ability to show a catalog's feed, deadlines, detail, tracking form and review queue from `@wow-two-beta/fe-events`.
- [ ] Ability for a reviewer to sign in through the catalog owner's Identity and review in the console.

### Iteration 6 — Verification on dev

- [ ] Deploy through Wheelhouse (`deploy.yml`), PostgreSQL, typed issuer and SCFD settings.
- [ ] A live Afisha record becomes a review candidate; nothing publishes unreviewed.
- [ ] Tests named for replay, out-of-order revisions, a crash around the cursor commit, a malformed record and a
  cross-organization read pass.
